# Implement an expanded todo CLI

Create a Python command-line application. Name the application file `todo.py`. Complete all requirements. Create the automated test file `test_todo.py`.

## Requirements

- **R01 — Runtime and storage.** Use only the Python standard library. Store the state in `.todo.json`. Store this file in the current working directory. Make the state available to subsequent invocations. Do not read files outside the current working directory. Do not write files outside the current working directory.
- **R02 — Commands.** Supply these commands: `add`, `list`, `complete`, `delete`, and `report labels`. Accept an option only when a requirement in this prompt defines the option.
- **R03 — Add.** Use this syntax: `python todo.py add <text> [--due YYYY-MM-DD] [--label LABEL ...]`. Create one incomplete todo. Write exactly `Added <id>: <text>` to stdout.
- **R04 — Identifiers.** Assign integer IDs. Assign `1` to the first todo. Do not reuse an ID. When the user deletes a todo, do not change an ID of a remaining todo.
- **R05 — Complete and delete.** The command `complete <id>` must complete an existing todo. Write exactly `Completed <id>: <text>` to stdout. The command `delete <id>` must remove an existing todo. Write exactly `Deleted <id>: <text>` to stdout.
- **R06 — Due dates.** The `--due` option is optional. The value must be a real Gregorian calendar date. The format must be exactly `YYYY-MM-DD`. Store a valid due date.
- **R07 — Labels.** The `--label` option is optional. The user can supply the option more than one time. Convert each label to lowercase. After conversion, each label must match `[a-z0-9][a-z0-9-]{0,19}`. Remove duplicate labels. Store the labels in ascending lexical order.
- **R08 — List display.** The `list` command must sort matching todos by ascending ID. For an incomplete todo, start the line with `<id>. [ ] <text>`. For a completed todo, start the line with `<id>. [x] <text>`. If the todo has a due date, append ` | due: <date>`. If the todo has labels, append ` | labels: <label1>,<label2>` after the due-date segment. Do not append a segment for metadata that is not present. If no todo matches, write no output.
- **R09 — List filters.** The `list` command accepts these filters: `--status open|completed|all`, `--due YYYY-MM-DD`, `--due-before YYYY-MM-DD`, and `--label LABEL`. If the user does not supply `--status`, use `all`. Include the date supplied to `--due-before` in the result range. Convert the label-filter value to lowercase. If the user supplies more than one filter, apply the filters with logical AND.
- **R10 — Grouped report.** The command `report labels` accepts the filters in R09. Apply the filters before you make the groups. Count a todo one time in each label group that the todo has. Put a todo that has no label in the `(unlabeled)` group. Sort labeled groups in ascending lexical order. If the `(unlabeled)` group exists, put this group after all labeled groups. Use exactly `<label>: total=<n> open=<n> completed=<n>` for each line. If no todo matches, write no output.
- **R11 — Validation failures.** Reject an unknown command. Reject an option that the prompt does not support. Reject a missing value. Reject an invalid ID. Reject a nonexistent ID. Reject an invalid date. Reject an invalid label. Reject an unexpected positional argument. Write a useful error to stderr. Exit with a nonzero status.
- **R12 — State integrity.** Validate the complete command before you change the state. If a command fails, do not create `.todo.json`. If a command fails, do not modify `.todo.json`. If stored JSON is malformed, report an error. If the stored schema is invalid, report an error. Do not discard or replace invalid stored data.
- **R13 — Existing state.** A stored todo object can have no `due` field. In this case, use no due date. A stored todo object can have no `labels` field. In this case, use no labels. This requirement supplies compatibility with the basic todo fixture.
- **R14 — Tests.** Use only the Python standard library for automated tests. Put the tests in `test_todo.py`. Test the core commands. Test persistence. Test due dates. Test labels. Test combined filters. Test grouped reporting. Test validation errors. Test state integrity. The command `python -m unittest -v` must run the tests.
- **R15 — Deliverables and scope.** Deliver `todo.py`. Deliver `test_todo.py`. Do not add a third-party dependency. Do not add network access. Do not add an unrelated feature. Do not add an unrelated file.
